GETTING STARTED / SYSTEM

Setup & diagnostics.

Install the controller, enroll worker nodes and configure your inference runtime.

01 / CONTROLLER

Install and launch

Python 3.11+ and private network connectivity are required.

python -m pip install -e .
python -m muldeaiserv serve

For LAN binding use --host 0.0.0.0 --allow-lan, with a strong admin token and preferably an HTTPS reverse proxy.

02 / AGENT

Connect computing devices

Generate a single-use token on the Device network page. Then run the agent from each Windows/Linux/macOS host.

python -m muldeaiserv.agent --server <controller-origin> --join-token <token>

iOS/Android currently use this browser interface. Native mobile inference workers are not yet implemented.

INTERACTIVE SETUP / NON-EXECUTING

Guided installation checklist

Select a runtime and target computer to obtain platform-specific, reviewable setup instructions. No commands are executed by this interface.

03 / DISTRIBUTED MODELS

Prepare a vLLM cluster

For one model split across GPUs: use Linux GPU hosts, identical vLLM container/runtime environments, fast networking, and Ray for multi-node execution. Model files must be available at consistent paths. The planner generates a command but does not deploy it.

Run diagnostics to inspect controller-host dependencies.
ENGINE RESEARCH / HETEROGENEOUS DEVICES

Other cluster runtimes

exo supports real model splitting on compatible Apple silicon MLX clusters; llama.cpp RPC offers experimental cross-device tensor offloading. Neither is installed or orchestrated automatically. Native Android/iOS memory sharing is not available in this release. See exo, llama.cpp RPC and the repository engine research notes.

Security: no default public API access, no remote shell execution, no direct public-backend URLs. vLLM documentation: Distributed serving guide ↗
